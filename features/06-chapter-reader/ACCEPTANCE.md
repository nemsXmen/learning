# Acceptance criteria

- [ ] Chapter renders server-side with highlighted code and a working outline
- [ ] Sidebar reflects real per-chapter status and is usable on mobile
- [ ] Reading progress and explicit completion both persist and never regress
- [ ] Locked chapters are refused server-side with an explanatory page
- [ ] Loading, empty, error, success and locked states implemented
- [ ] Axe passes; keyboard-only journey works; AA contrast in both themes
- [ ] No client-side Markdown parsing and no answer key in the payload
- [ ] Automated tests pass
