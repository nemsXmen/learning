## API or event boundary

- Both endpoints require an authenticated session, and refuse a locked chapter with
  `403 CHAPTER_LOCKED` and its reason. Enforcing the lock where the content is
  served — not only where the catalogue displays it — is what makes a direct URL
  useless (features/06-chapter-reader).
- `content:sync` is a CLI command, not an endpoint.

## Validation and errors

- Unknown technology or chapter → `404 CONTENT_NOT_FOUND`.
- Content that fails validation at runtime → `500 CONTENT_INVALID`, logged with the
  offending path; the previous cached render is served if one exists.
- Path parameters are slug-validated; no path segment reaches the filesystem unescaped.

## Change: the graph is bundled, not read from disk

`ContentService` imports a module generated by `pnpm content:bundle` instead of
walking `content/` at boot (docs/decisions.md). The payloads below are unchanged.
Two consequences: the boot check now fails on an empty bundle rather than on an
invalid tree, and `content:sync` projects the same bundled graph the API serves,
so the two cannot disagree.

## Invariants

- `answer` and `explanation` never appear in a response from this feature.
- Rendered HTML is sanitized; no inline script or event handler survives.
- `contentVersion` in a chapter response and its quiz response always match.
- `content:sync` is idempotent: running it twice changes nothing.
