# Acceptance criteria

- [ ] Plans come from `packages/learning-engine` and are stored, not recomputed
- [ ] Sessions respect the chosen duration and target explained weak or due skills
- [ ] Steps run in order, are resumable, and reuse the quiz feedback shape
- [ ] Completion applies mastery and XP exactly once and shows per-skill deltas
- [ ] The unavailable case is a first-class state with a next action, not an error
- [ ] Loading, empty, error, success, disabled and expired states implemented
- [ ] Fully keyboard operable; step progress announced; reduced motion respected
- [ ] Automated tests pass
