# Acceptance criteria

- [ ] Catalog endpoints match the contract, scoped to the authenticated user
- [ ] Lock state and its reason are computed server-side and surfaced in the UI
- [ ] Progress aggregation is consistent across chapter, module and technology
- [ ] Continue action resumes the correct chapter
- [ ] Loading, empty, error, success and locked states are implemented
- [ ] Roadmap is accessible without relying on the visual sequence
- [ ] Direct URL access to a locked chapter is refused server-side
- [ ] Automated tests pass
